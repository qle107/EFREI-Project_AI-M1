## 1. Project Overview

**AISCA** (AI Semantic Coverage Analysis) is an AI-powered movie recommendation system that combines:

- **Semantic embeddings** (Sentence-BERT) for understanding movie content and user preferences
- **Multi-dimensional scoring** across mood, theme, narrative style, and description
- **Generative AI** (LLM: **Ollama**, **Claude**, or **Gemini** — switchable in Settings or on the Recommend page) to produce natural-language explanations of recommendations

The system is designed for M1-level AI coursework and demonstrates retrieval-augmented generation (RAG), semantic search, and hybrid recommendation approaches.

## 4. Models

### 4.1 Sentence-BERT (SBERT)

- **Model**: `sentence-transformers/all-MiniLM-L6-v2`
- **Purpose**: Encode text into 384-dimensional semantic vectors
- **Usage**:
  - User profile blocks (mood, theme, style, description)
  - Movie semantic blocks (Mood, Theme, NarrativeStyle, Description)
  - Combined text for the alternative RAG pipeline

**How it works**: Text is tokenized, passed through a MiniLM backbone, and mean-pooled to produce a fixed-size vector. Similar texts map to nearby vectors in the embedding space.

### 4.2 Taxonomy (Keyword-Based Extraction)

The project uses a custom taxonomy to map overview text to semantic labels:

**Mood Keywords** (`MOOD_KEYWORDS`):


| Label     | Keywords                           |
| --------- | ---------------------------------- |
| dark      | crime, killer, murder, corruption  |
| uplifting | family, gift, hope                 |
| tense     | struggle, danger, kidnap, blizzard |
| heroic    | hero, super, fight                 |


**Theme Keywords** (`THEME_KEYWORDS`):


| Label    | Keywords           |
| -------- | ------------------ |
| fantasy  | magic, gift, power |
| crime    | killer, corruption |
| survival | stranded, blizzard |
| family   | family, child      |


**Style Keywords** (`STYLE_KEYWORDS`):


| Label   | Keywords           |
| ------- | ------------------ |
| action  | fight, danger      |
| mystery | discover, uncovers |
| drama   | family, life       |


If no keyword matches, the label is `"neutral"`.

### 4.3 LLM (Ollama, Claude, or Gemini)

The system supports **three switchable backends** for natural-language explanations:

| Provider | Model (default) | Config | Where to switch |
| -------- | ---------------- | ------ | ---------------- |
| **Ollama** | `phi3:mini` | `LLM_URL`, `LLM_MODEL` in `.env` | Settings or Recommend page |
| **Claude** | `claude-3-5-haiku-20241022` | `ANTHROPIC_API_KEY` in `.env` or in Settings | Settings or Recommend page |
| **Gemini** | `gemini-1.5-flash` | `GEMINI_API_KEY` in `.env` or in Settings | Settings or Recommend page |

**Requirements**: For Ollama, run `ollama run phi3` (or equivalent) locally. For Claude or Gemini, set the corresponding API key in `.env` or in the Settings page. The active provider can be changed at any time without restarting the API.

## 6. Techniques

### 6.1 Semantic Block Extraction

**Location**: `src/preprocessing/block_builder.py`

Text is lowercased and scanned with regex `\b{keyword}\b` for word-boundary matches. Each taxonomy label is assigned if any of its keywords appear. Multiple labels can be assigned (e.g. `"dark, uplifting"`).

```python
# Example: Overview contains "corruption" and "family"
# → Mood: dark (corruption), uplifting (family)
# → Theme: crime (corruption), family (family)
```

### 6.2 Cosine Similarity

**Formula**: \text{similarity}(A, B) = \frac{A \cdot B}{A B}

- Range: [-1, 1] (typically [0, 1] for normalized embeddings)
- Used to compare user profile vectors with movie block vectors

**Implementation**: `sklearn.metrics.pairwise.cosine_similarity`

### 6.3 AISCA Weighted Score


\text{CoverageScore} = 0.35 \cdot \text{MoodScore} + 0.25 \cdot \text{ThemeScore} + 0.20 \cdot \text{StyleScore} + 0.15 \cdot \text{DescScore} + 0.05 \cdot \text{RecencyScore}


- **Mood** (35%): Emotional tone match
- **Theme** (25%): Genre/thematic match
- **Style** (20%): Narrative pacing match
- **Description** (15%): Semantic match to free-text description
- **Recency** (5%): Light tiebreaker favoring newer releases (exponential decay)

The score is dominated by semantic similarity (95%) with recency as a minor tiebreaker. The recency score uses exponential decay: `exp(-(current_year - release_year) / 10)`.

### 6.4 Retrieval-Augmented Generation (RAG)

1. **Retrieve**: Semantic search returns top-K movies.
2. **Augment**: Top movies + scores are formatted into a context string.
3. **Generate**: LLM receives user request + context and produces an explanation.

This limits LLM hallucinations by grounding output in actual retrieved movies and scores.

### 6.5 Embedding Representation

- **Dimension**: 384 (MiniLM-L6-v2)
- **Normalization**: Typically L2-normalized by the model
- **Storage**: NumPy arrays (`.npy`) for fast loading

## 7. Functionalities

### 7.1 API Overview (Summary)

The backend exposes a versioned REST API under `/api/v1` with:

- **OpenAPI**: Live docs at `/docs` (Swagger) and `/redoc`; static spec in `docs/openapi.json` / `docs/openapi.yaml` (see [§8 Backend API](#8-backend-api-rest-openapi-jwt)).
- **Authentication**: JWT (login/refresh/me) with Bearer auth on protected routes.
- **Recommendations**: Custom recommendation requests, one-click preset requests, and persisted user history.
- **Catalog & movies**: API for dropdown options and paginated movie browsing/detail.
- **Runtime settings**: Authenticated settings API to switch LLM provider and tune generation/cache parameters at runtime.

### 7.2 User Profile Encoding

**Input**: Hybrid questionnaire with:

- `description` (str): Free-text preference (enriched by GenAI if < 5 words)
- `preferred_mood`, `preferred_genre`, `preferred_style` (str): Guided chip selection
- `preferred_era` (str, optional): Guided question — time period preference
- `preferred_director` (str, optional): Guided question — director / style reference
- `mood_intensity`, `theme_interest`, `style_interest` (int, 1-5): Likert-scale auto-declaration

**Output**: Four embedding vectors (mood, theme, style, description).

**Block construction**:

- Mood: `"The user wants a {mood} mood with intensity level {intensity}"`
- Theme: `"The user prefers {genre} themes with interest level {interest}"`
- Style: `"The user enjoys {style} narrative pacing with interest level {interest}"`
- Description: Raw `description` text + era context + director context (when provided)

### 7.3 Coverage Scoring

Compares user profile embeddings with precomputed movie block embeddings, then applies:

`0.35 * mood + 0.25 * theme + 0.20 * style + 0.15 * desc + 0.05 * recency`

Returns the top 3 movies by `CoverageScore`.

### 7.4 Recommendation Engine

The recommendation pipeline:

1. Encodes the profile with SBERT.
2. Scores all movies with cosine similarity + weighted aggregation.
3. Returns top-3 ranked movies with per-axis scores, `film_id`, and `poster_url`.
4. Calls the selected LLM to generate explanation + cinephile profile.

### 7.5 GenAI Integration

Three controlled GenAI use cases, via the selected LLM (Ollama, Claude, or Gemini; cost-aware with cache):

1. **Short-description enrichment (EF4.1)**: If description has fewer than 5 words.
2. **Recommendation explanation (EF4.2/EF4.3)**: Grounded in top-3 movies and score breakdown.
3. **Cinephile profile synthesis**: 2-sentence user taste profile.

Additional metadata returned with each recommendation:

- `description_enriched` (bool)
- `cached` (bool)
- `preset_id` (optional, when using preset flow)
- `llm_provider` (`ollama`, `anthropic`, or `gemini`)

### 7.6 Preset Queries (Fast Demo Flow)

The system includes curated presets in `src/genAi/preset_queries.py` (e.g., dark crime thriller, epic fantasy, psychological horror):

- `GET /api/v1/recommendations/presets` lists all presets.
- `POST /api/v1/recommendations/presets/{preset_id}` runs the full AISCA pipeline using preset fields.
- LLM response cache makes repeated preset calls near-instant, useful for demos and soutenance.

### 7.7 Recommendation History (Traceability)

Each recommendation generation is persisted per user in a lightweight SQLite store:

- Storage: `data/recommendation_history.db`
- Module: `src/core/recommendation_history.py`
- Endpoints:
  - `GET /api/v1/recommendations/history`
  - `GET /api/v1/recommendations/history/{history_id}`

This supports reproducibility, UX continuity, and report evidence (what was generated, when, and from which request).

### 7.8 Runtime LLM Settings

The settings feature allows changing LLM behavior without restarting the API:

- Backend runtime config: `src/core/llm_runtime_config.py`
- Settings router: `src/api/routers/settings.py`
- Frontend page: `frontend/src/app/settings/page.tsx`

Supported runtime controls:

- Provider switching: Ollama / Claude / Gemini
- Model and token settings (`llm_model`, `num_predict`, `anthropic_model`, `gemini_model`, etc.)
- Temperature
- Cache policy (`cache_ttl`, `cache_max_size`)
- Optional runtime API keys (stored in memory only, never returned by API)
- Cache purge endpoint: `POST /api/v1/settings/llm/clear-cache`

### 7.9 Visualization (Radar Charts)

- **Backend**: `src/visualization/radar_plot.py` (matplotlib, for CLI/Streamlit)
- **Frontend**: `frontend/src/components/RadarChart.tsx` (SVG, interactive)
- **Axes**: Mood, Theme, Style, Description
- **Values**: Block scores (0-1) per recommended movie

### 7.10 Alternative RAG Pipeline

- **Class**: `MovieRecommenderPipeline`
- **Input**: Free-text user query
- **Output**: Top-K movies + LLM explanation
- **Difference from AISCA**: Single combined embedding per movie (no block decomposition)

| PUT    | `/api/v1/settings/llm`                    | Bearer | Update runtime LLM settings                                                                         |
| POST   | `/api/v1/settings/llm/clear-cache`        | Bearer | Clear in-memory LLM response cache                                                                  |


### 8.4 Recommendation Request Body

Get valid options for mood / genre / style from `GET /api/v1/catalog/options` so values align with the catalog.


| Field                | Meaning                                           | Valid / Notes                                              |
| -------------------- | ------------------------------------------------- | ---------------------------------------------------------- |
| `description`        | Free-text preference; tone, themes, what to avoid | Min 10 characters; enriched by GenAI if < 5 words          |
| `preferred_mood`     | Atmosphere (e.g. dark, tense, uplifting)          | Use `catalog/options` → `moods`                            |
| `preferred_genre`    | Theme / genre (e.g. crime, science fiction)       | Use `catalog/options` → `genres`                           |
| `preferred_style`    | Pacing / style (e.g. mystery, action, drama)      | Use `catalog/options` → `styles`; short keywords work best |
| `preferred_era`      | Time period (optional guided question)            | E.g. `"2010s"`, `"90s"`, `"Recent (2020+)"`               |
| `preferred_director` | Director or style reference (optional)            | Free text, e.g. `"Christopher Nolan"`                      |
| `mood_intensity`     | How strong the mood should be                     | **1** = subtle → **5** = central                           |
| `theme_interest`     | How important theme is to the match               | **1** = secondary → **5** = very important                 |
| `style_interest`     | How important pacing/style is                     | **1** = matters little → **5** = very important            |


Example request:

```json
{
  "description": "I want a slow-burn sci-fi thriller with a mysterious vibe, ethical dilemmas about AI, and a tense atmosphere. Minimal romance, smart dialogue, and a satisfying twist.",
  "preferred_mood": "tense",
  "preferred_genre": "science fiction",
  "preferred_style": "mystery",
  "preferred_era": "2010s",
  "preferred_director": "Denis Villeneuve",
  "mood_intensity": 5,
  "theme_interest": 4,
  "style_interest": 4
}
```

### 8.6 Movies & Catalog (UI-Oriented)

- `**GET /api/v1/movies**`: Query params `skip`, `limit`, optional `search`, `mood`, `genre`. Each item includes `film_id`, `title`, `mood`, `theme`, `narrative_style`, `emotional_tone`, `poster_url`, `vote_average`.
- `**GET /api/v1/movies/{film_id}**`: Full detail including `description`, `overview`, `poster_url`, `release_date`, `vote_average`.
- `**GET /api/v1/catalog/options**`: Returns `{ "moods": [...], "genres": [...], "styles": [...] }` for dropdowns and recommendation form.

Poster URLs come from the raw dataset (`Database_Cleaned.csv`, `Poster_Url`); the movie catalog service merges referential and raw data by index.
